# Project Map 安装、部署与更新

本文说明如何将 Project Map 部署到 Codex、Claude Code 和目标项目，以及如何在多台电脑之间快速同步、验证、更新和回滚。

> 适用范围：本能力包面向 Codex 本地工作区，不是普通 ChatGPT 对话中的云端插件。ChatGPT/Codex Desktop 的账号或任务同步不应被当作本机 Skill、CLI 或项目文件的部署机制。

## 文档职责与单一事实来源

为避免安装说明在多个文件之间漂移，维护时遵守以下边界：

| 文件 | 唯一职责 |
| --- | --- |
| `install.sh` | macOS/Linux 一键安装的实际行为、默认值与参数 |
| `uninstall.sh` | macOS/Linux 一键卸载、可恢复重置的实际行为与参数 |
| 本文 | 部署模型、Windows 边界、更新、回滚、验收与排障 |
| `README.md` | 项目概览、唯一的一键安装入口与日常使用示例 |
| `docs/design/`、`docs/superpowers/plans/` | 历史设计和实施证据，不作为运行手册 |

规则：精确的手工安装命令只在本文维护；README 不复制这些命令。脚本默认值变更时，必须同步本文并由测试校验。历史文档中的命令即使保留，也不得作为当前安装依据。

## 部署模型

普通用户只面对两个层次：

```text
设备：./install.sh --runtime claude|codex 一次安装 GSD + Skill + CLI
项目：在 Codex 中输入“$project-map 初始化新项目”，或在 Claude Code 中输入“/project-map 初始化新项目”
```

CLI 安装在 `~/.local/bin/project-map`，由所有项目共享；项目只保存 `.planning/` 数据，不再向每个项目重复写入 npm 依赖。

## 每台设备的五分钟部署清单

1. 安装 Git、Node.js 24+ 和 Codex CLI 或 Codex Desktop。
2. 克隆本仓库并运行 `./install.sh --runtime claude` 或 `./install.sh --runtime codex`。
3. 重启相应运行时，在项目目录输入对应的 project-map 命令。

安装脚本内部负责版本、目录和可执行程序验收。普通用户无需再运行 Skill installer、GSD installer 或项目级 `npm install`。

## 推荐：克隆后运行一键安装

macOS 或 Linux 上，设备级安装只需克隆本仓库并运行脚本：

```bash
git clone https://github.com/githuangjunwen/Project-initialization-skill.git
cd Project-initialization-skill
./install.sh --runtime codex
```

这一个命令会完整安装设备级 GSD full profile、全部 Codex 子 Agent、`project-map` Skill 和共享 CLI，再把 Desktop 的 GSD Skill 展示收敛为核心集合。无需为每个项目再次安装。安装后若要立即验证已有项目，可传入真实目录：

```bash
./install.sh --runtime codex --project /opt/ceshi/ds-wechat-api-ubuntu
```

`--project` 不是安装必需参数；上面的路径只用于安装后验证。新项目无需 `package.json`，在项目目录打开 Codex 后输入 `$project-map 初始化新项目` 即可。

安装命令必须明确指定目标运行时：

```bash
./install.sh --runtime claude
./install.sh --runtime codex
```

Claude Code Skill 安装到 `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/project-map`，GSD 通过其官方 `--claude --global` 投射安装；Codex 文件仍位于 `~/.agents/skills` 与 `~/.codex`。两端共享 `~/.local/bin/project-map` 和项目数据。Claude Code 中调用 `/project-map`，Codex 中调用 `$project-map`。

该命令会：

1. 检查 Git、Node.js、npm 与 npx；安装 GSD 1.11.0 时要求 Node.js 24+。
2. 默认完整安装 GSD `1.11.0` full profile，确认至少 34 个 Agent TOML、Hooks 与完整工作流可用，然后只展示 8 个核心 GSD Skills。
3. 将 `project-map` Skill 安装到 `$HOME/.agents/skills/project-map`。
4. 将当前源码克隆打成临时包，并把同源 CLI 安装到 `$HOME/.local/bin/project-map`；安装后不依赖源码目录继续存在。
5. 传入 `--project` 时验证或初始化该目录；不修改项目 `package.json`。

首次初始化也可以在同一条命令完成，但必须由用户提供真实输入：

```bash
./install.sh --runtime codex \
  --project /opt/ceshi/ds-wechat-api-ubuntu \
  --init-title "项目名称" \
  --init-text "项目的原始想法"
```

常用选项：

- `--skip-gsd`：设备已由其他方式管理 GSD 时跳过 GSD 安装。
- `--runtime claude|codex`：必填，选择唯一的目标运行时。
- `--skip-cli`：高级场景下跳过设备级共享 CLI。
- `--force-skill`：现有 Skill 内容不同时，先备份再替换。
- `--gsd-version` / `--gsd-profile`：显式覆盖 GSD 版本与 profile；为保证子 Agent、Hooks 和工作流完整，本安装器只接受 `full`。
- `--gsd-surface core|full`：只控制 ChatGPT Desktop/Codex 中可见的 GSD Skills，默认 `core`；使用 `full` 可临时展示全部 Skills。
- `--allow-dirty`：允许从有未提交改动的开发克隆安装；正式部署不应使用。

脚本支持重复执行：内容一致的 Skill 会跳过；不同内容默认停止，避免覆盖来源不明的安装。当前只支持 macOS 与 Linux，Windows 继续使用后文 PowerShell 步骤。

## 推荐：一键卸载与重新测试

一键卸载设备级 GSD、`project-map` Skill 和共享 CLI：

```bash
./uninstall.sh --runtime codex
```

卸载命令也必须明确指定目标运行时：`./uninstall.sh --runtime claude` 或 `./uninstall.sh --runtime codex`。两种运行时的 Skill 与 GSD 分开备份和删除；若另一端仍安装，卸载器会保留共享 CLI。

旧版本曾向项目写入 npm 依赖时，可指定项目一并清理；项目数据仍默认保留：

```bash
./uninstall.sh --runtime codex --project /opt/ceshi/ds-wechat-api-ubuntu
```

需要从零验证 CLI 数据初始化和 GSD surface 时：

```bash
./uninstall.sh --runtime codex \
  --project /opt/ceshi/ds-wechat-api-ubuntu \
  --reset-data \
  --reset-surface
```

`--reset-data` 会把项目数据移动为 `.planning/project-map.uninstalled.<时间戳>`。默认卸载 GSD 时会自动备份 surface 状态；使用 `--keep-gsd` 时，可额外传入 `--reset-surface` 单独重置。备份位于 `~/.project-map-uninstall-backups/`。卸载器使用 GSD 官方 `--uninstall` 入口，只清理 GSD 或本安装器明确管理的文件，不会删除整个 `~/.codex`、整个 `~/.agents/skills` 或源码仓库。

如果其他项目仍依赖全局 GSD，使用 `--keep-gsd`；如果只想移除共享 CLI，且需保留用户级 `project-map` Skill，再同时使用 `--keep-skill`。

## 边界与原则

### Skill 不等于 CLI

Skill 负责识别“初始化新项目”“推进 E-002”等意图并约束工作流。设备级 `project-map` CLI 负责读写各项目 `.planning/project-map/` 中的数据；一键脚本会同时安装两者。

### 双运行时共享数据，不共享配置目录

Codex 与 Claude Code 使用同一个 CLI 和 `.planning/project-map/` 规范数据。Codex Skill/GSD/Agent 位于 Codex 配置目录，Claude Code 对应文件位于 `CLAUDE_CONFIG_DIR`（默认 `~/.claude`）。安装或卸载一个运行时不会覆盖另一个运行时的 Skill 与 GSD。

### Desktop 同步不等于文件部署

`~/.agents/skills/`、GSD runtime 和 `~/.local/bin/project-map` 都是设备上的文件。多台设备即使登录同一账号，也需在每台设备按所用运行时各运行一次 `./install.sh --runtime claude` 或 `./install.sh --runtime codex`。

### 开发态与稳定版分开

- 开发态：使用 `--allow-dirty` 从当前工作树安装测试版本。
- 稳定版：检出 Git 标签后运行脚本，确保多台设备行为一致。

## 安装前提

每台设备需要：

- Git。
- Project Map CLI 需要 Node.js 18 或更高版本。
- 默认安装的 GSD 1.11.0 需要 Node.js 24 或更高版本；Node.js 18–23 只能配合 `--skip-gsd` 使用本项目自身能力。
- Codex CLI 或能打开本地代码工作区的 Codex Desktop。
- Project Map 源码仓库和目标项目仓库的访问权限。
- 如需 GSD 交接，还需要单独安装兼容的 GSD runtime；本项目当前核对基线为 `1.11.0`。

克隆源码后先运行：

```bash
node --version
npm --version
npm run check
```

## 高级安装说明

默认行为是“full 完整能力 + core 精简展示”：全部 Agent、Hooks、工作流和隐藏 Skill 副本都保留，但 Desktop 只发现 8 个核心 GSD Skills。需要临时展示全部 Skills 时运行：

```bash
./install.sh --runtime codex --gsd-surface full
```

恢复精简展示时重新运行 `./install.sh --runtime codex`，或显式使用 `./install.sh --runtime codex --gsd-surface core`。不要手工删除 `gsd-*` 或 `.codex/agents/gsd-*` 文件。

surface 只改变顶层 Skill 入口的可发现性，不删除 `~/.codex/agents`、Hooks 或 GSD 工作流。因此 `gsd-plan-phase` 和 `gsd-execute-phase` 仍可按 GSD 设计调用子 Agent。非核心的显式入口（例如 `$gsd-debug`）在 core surface 下不可直接选择；使用前先切换为 full surface。

多设备使用时，每台设备各检出同一个 Git 标签，并按所用运行时运行对应的显式安装命令；项目仓库只同步 `.planning/` 数据和代码，不再同步 Project Map npm 依赖。

Windows 暂不支持这两个 Bash 一键脚本；应在 WSL 中运行，或按照 Codex 与 GSD 各自的 Windows 安装方式部署。不要只安装一个 Skill 后宣称完整工作流可用。

## 目标项目的首次初始化

在目标目录打开 Codex，输入：

```text
$project-map 初始化新项目
```

Skill 会确认项目名称和未经改写的原始想法，初始化 Project Map，并在缺少 GSD 项目文件时继续执行 `$gsd-new-project`。无需安装项目 npm 依赖。

`init` 会拒绝覆盖已有 Project Map。建议将以下内容提交到目标项目的 Git 仓库：

- `.planning/project-map/index.json`
- `.planning/project-map/sources/`
- `.planning/project-map/nodes/`
- `.planning/project-map/decisions/`
- `.planning/project-map/CURRENT.md`
- `.planning/project-map/PROJECT-MAP.md`

如果需求文档包含敏感商业信息，应使用私有仓库并确认数据分类要求。不要用聊天记录代替项目仓库保存规范数据。

## 多设备日常操作协议

Project Map 的规范 JSON 应当使用“同一时间只由一台设备写入同一分支”的规则。任务开始前：

```bash
git status --short
git pull --ff-only
project-map check --json
```

任务结束前：

```bash
project-map check --json
git status --short
git add .planning/project-map
git commit -m "docs: 更新项目地图"
git push
```

如果两台设备已同时修改项目地图：

1. 停止继续写入。
2. 不要手工合并 `CURRENT.md`、`PROJECT-MAP.md` 或就绪标记。
3. 根据权威来源合并 `sources/`、`nodes/`、`decisions/` 和 `index.json`。
4. 运行 `project-map check --json`。
5. 检查通过后才能运行 `project-map rebuild --json`。

## 更新流程

### 发布新版本

1. 完成源码和文档更新。
2. 同时更新 `package.json` 与 `capability/capability.json` 版本。
3. 更新兼容性或迁移说明。
4. 运行 `npm run check`。
5. 提交变更，创建并推送版本标签。

发布前检查：

```bash
node -p "require('./package.json').version"
node -p "require('./capability/capability.json').version"
npm run check
git status --short
```

两个版本号必须一致，发布前工作区应当干净。

### 升级每台设备

```bash
git fetch --tags
git checkout <release-tag>
npm run check
./install.sh --runtime codex
```

- `./install.sh --runtime <claude|codex>` 会把指定运行时的设备级 Skill 与共享 CLI 更新到当前 commit。
- 各项目不保存 Project Map npm 依赖，无需修改锁定文件。

升级后在目标项目验证：

```bash
project-map check --json
```

然后新建 Codex 任务，输入“查看项目状态”或“推进 <ID>”验证 Skill 路由。

## 回滚流程

回滚时必须同时对齐 Skill 和 CLI：

1. 每台设备检出上一个稳定标签。
2. 重新执行 `./install.sh --runtime <claude|codex> --force-skill`，同步回滚指定运行时的设备级 Skill 与 CLI。
3. 运行 `project-map check --json`。
4. 新建 Codex 任务验证 Skill。

`project-map check` 通过之前不要运行 `rebuild`。如果新版本改变了规范数据结构，必须使用该版本提供的迁移流程，不得根据生成的 Markdown 手工重建数据。

## 常见问题

### Codex 没有识别 Skill

1. 确认 `~/.agents/skills/project-map/SKILL.md` 存在。
2. 如使用链接，确认链接目标在本机存在。
3. 确认没有只安装到 `~/.codex/skills/project-map`；该目录不是当前用户级发现目录。
4. 在 Codex CLI 中运行 `/skills` 或输入 `$project-map` 验证显式发现。
5. 新建 Codex 任务；仍无法识别时，完全退出并重启 Codex。

### 能看到 project-map，但看不到 GSD Skills

`project-map` 与 GSD 是独立安装。先检查：

```bash
test -f "$HOME/.codex/gsd-core/VERSION"
find "$HOME/.agents/skills" -mindepth 2 -maxdepth 2 -path '*/gsd-*/SKILL.md' -print
```

runtime 不存在时执行本指南的 GSD 安装命令；只缺少个别 GSD Skill 时检查 GSD surface/profile。

### Skill 被识别，但 CLI 不可用

确认 `~/.local/bin/project-map` 可执行；若 shell 仍找不到命令，将 `$HOME/.local/bin` 加入 `PATH`。也可以直接重新运行本仓库的 `./install.sh --runtime <claude|codex>`，Skill 本身会回退到该绝对路径，不依赖 shell 的 `PATH`。

### 两台设备行为不同

依次比较本仓库 Git 标签、`~/.local/bin/project-map`、Skill 内容、Node.js 版本和 GSD 版本。

### 升级后生成文档仍是旧内容

```bash
project-map check --json
project-map rebuild --json
```

只有第一条命令通过后才能运行第二条。

## 发布状态检查

不要在长期文档中保存“当前设备已安装”或“仓库尚无标签”等时间快照。发布前直接检查实时状态：

```bash
git remote -v
git tag --list --sort=-version:refname
node -p "require('./package.json').version"
node -p "require('./capability/capability.json').version"
./install.sh --help
```

只有两个清单版本一致、目标 commit 或标签已推送且安装测试通过，才能对外宣称该版本可复现部署。

## 官方文档复核记录

本文依据 [OpenAI 官方 Codex Skills 文档](https://developers.openai.com/codex/skills)维护以下约束：

- 用户级本地 Skill 目录是 `$HOME/.agents/skills`。
- 仓库级 Skill 位于从当前目录到仓库根目录范围内的 `.agents/skills`。
- Codex 会自动检测 Skill 变化；新 Skill 未出现时应重启 Codex。
- Codex CLI 可通过 `/skills` 或输入 `$` 显式选择 Skill。
- `agents/openai.yaml` 可提供 Codex Desktop 的显示元数据。

本指南中的 GSD 1.11.0 路径与命令另外根据本机安装产物和 `gsd-tools.cjs` 的实际命令路由核对，不把它们冒充为 OpenAI 产品约定。

Claude Code 路径与命令依据 Anthropic 官方 Skills、Plugin 和 VS Code 文档维护：个人 Skills 位于 `~/.claude/skills`，Claude Code 使用 `/skill-name` 调用；VS Code 扩展面板捆绑私有 CLI，但不会把 `claude` 加入 shell `PATH`，因此终端验收需要单独安装 Claude Code CLI。
